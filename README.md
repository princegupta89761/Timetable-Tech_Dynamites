# Buildsaur — Clash-Free Campus Timetable Generator with Git-Style Version Control

> **Indigo Tech Fest — Software Track 1**  
> *"A timetable generator that never clashes, and remembers every change like Git."*

---

## 🚀 Overview

Creating university campus timetables by hand inevitably causes clashes: a professor double-booked across batches, two classes assigned to the same room, or lab sessions fragmented across different days.

**Buildsaur** solves this with a two-part system:
1. **Constraint-Satisfaction Generator (OR-Tools CP-SAT):** Automatically creates a mathematically verified, 100% clash-free timetable satisfying all capacity, room type, teacher availability, and consecutive lab block constraints in under 3 seconds.
2. **Git-Style Timetable Version Control (VCS):** Every schedule generation or edit creates a permanent commit (`c0001`, `c0002`...). You can view plain-English diffs between any two versions, revert mistakes without rewriting history, and prevent invalid manual edits with pre-commit validation.

## 📐 The 8 Hard Constraints Enforced

Every timetable generated by the solver or modified by a user is validated against the 8 hard constraints in [`docs/contract.md`](docs/contract.md):

1. **Batch Clash:** A batch has at most one lecture per `(day, period)`.
2. **Teacher Clash:** A teacher is never scheduled in two places at the same `(day, period)`.
3. **Room Clash:** A room is occupied by at most one class per `(day, period)`.
4. **Room Fit:** `room.capacity >= batch.size` and `room.type == subject.room_type` (e.g. labs require lab rooms).
5. **Teacher Availability:** Lectures never land on a teacher's marked unavailable periods.
6. **Teacher Max Per Day:** Total periods taught by a teacher in a single day does not exceed `max_per_day`.
7. **Coverage:** Every requirement gets exactly `lectures_per_week` periods scheduled.
8. **Lab Blocks:** Requirements with `block_size: 2` occupy two consecutive periods on the same day in the same room.

## ⚡ Quickstart

### 1. Prerequisites
- Python 3.10+ (tested on Python 3.14)
- Git

### 2. Setup Virtual Environment
```bash
# Clone the repository
git clone https://github.com/princegupta89761/Timetable-Tech_Dynamites.git
cd Timetable-Tech_Dynamites

# Create and activate virtual environment
python -m venv venv

# Windows (PowerShell):
.\venv\Scripts\Activate.ps1
# Linux / macOS:
source venv/bin/activate

# Install dependencies
pip install -r requirements.txt
```

### 3. Run the Backend Service
```bash
python main.py
```
*The service runs on `http://localhost:8000` with interactive Swagger docs at `http://localhost:8000/docs`.*

### 4. Run the Test Suite
```bash
pytest -v
```
All 39 tests cover the solver engine, infeasibility pre-checks, benchmark performance, constraint validator, VCS commit snapshotting, plain-English diffs, and end-to-end FastAPI integration.

## 📡 REST API Reference

Base path: `/api`. All error responses follow the standard format:
`{"error": {"code": "CLASH|INFEASIBLE|TIMEOUT|NOT_FOUND|BAD_REQUEST", "message": "...", "details": [...]}}`.

| Method | Endpoint | Purpose | Request Body | Response |
|---|---|---|---|---|
| `GET` | `/api/problem` | Retrieve active problem configuration | None | `ProblemInput` |
| `PUT` | `/api/problem` | Replace active problem configuration | `ProblemInput` | `ProblemInput` |
| `POST` | `/api/generate` | Run CP-SAT solver & commit new timetable | `{"message": "..."}` | `{"commit": Commit}` |
| `GET` | `/api/timetable` | Get active timetable at current `HEAD` | None | `Timetable` |
| `POST` | `/api/edit` | Validated manual slot move / change | `{"message", "slot_key", "new"}` | `{"commit": Commit}` or `400 CLASH` |
| `GET` | `/api/commits` | List commit history (newest first, no snapshots) | None | `[CommitSummary]` |
| `GET` | `/api/commits/{id}` | Get full commit with complete timetable snapshot | None | `Commit` |
| `GET` | `/api/diff?from=&to=` | Plain-English diff between two commits | Query params `from` and `to` | `Diff` |
| `POST` | `/api/revert` | Restores snapshot from a past commit | `{"commit_id": "c0001"}` | `{"commit": Commit}` |
| `GET` | `/api/view` | Grid view for `batch=`, `teacher=`, or `room=` | Query param (`batch`, `teacher`, or `room`) | `GridView` |
| `POST` | `/api/seed` | Reset problem data to seeded demo dataset | None | `{"ok": true}` |

## 🔍 The VCS Diff Engine

Traditional diff engines compare raw text lines. Buildsaur's timetable diff engine matches scheduled slots by requirement identity and occurrence order.

### Example Diff Output
```json
{
  "from": "c0001",
  "to": "c0002",
  "changes": [
    {
      "type": "moved",
      "batch_id": "b_se_a",
      "requirement_id": "q_b_se_a_s_dbms",
      "from": { "day": 1, "period": 2, "room_id": "r101" },
      "to":   { "day": 2, "period": 4, "room_id": "r104" },
      "text": "SE-A DBMS (Prof. Sharma): Tue 11:15 Room 101 -> Wed 14:00 Room 104"
    }
  ],
  "summary": { "moved": 1, "added": 0, "removed": 0, "changed": 0 }
}
```

If a manual edit creates a clash (e.g. moving a class into an occupied room or an unavailable teacher's period), the API rejects the request with HTTP `400 CLASH` and creates **no commit**, keeping history clean.
